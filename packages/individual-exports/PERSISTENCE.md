# Individual export adapter handoff

This package is a service boundary, not a deployed export endpoint. The memory adapter is for tests/demo, defaults to deny, and does not survive process restart. No public route or download URL is supplied. Integration requires production authority, snapshot, store, and key adapters.

`resolveSelection` accepts only a trusted session actor and scope/format DTO. Resolve exact selectors server-side. Residents may export only themselves; literal staff may export authorized requests/proposals; caregiver-only access remains disabled pending the `exports.read` capability. Admin/support/partner alone confer no export authority.

The snapshot adapter must use one checked-out connection with tenant context and one read-only REPEATABLE READ transaction. Return rows and independent counts together, with the first query's timestamp and source version. Every row must have a unique nonempty string `id` within its table. Audit events additionally carry their selected `resource_id`; multiple distinct events for a selected resource are valid. Profile/request/proposal identities and audit resource coverage are verified exactly. Counts detect omissions only when calculated independently. The adapter remains responsible for tenant/subject predicates, consent/history/recommendation ownership, and completeness inside each selected resource: the service cannot prove those properties from arbitrary JSON rows alone.

Implement `commitReadyIfAuthorized` and `authorizeReleaseAndRecord` as purpose-specific database transactions. Reload durable job state; lock the authority/revocation rows or use a serializable equivalent that also governs revocation writes. Check current roles, exact selector access, tenant/subject, and expiry using transaction time. Ready commits require generating state and immutable original job metadata. Persist encrypted artifact and ready metadata together. Release commits require ready state and record an audit only after current authorization succeeds. Return false without artifact/audit mutation on denial. Never compose an asynchronous authorization boolean with a later independent write. The successful release transaction is the authorization linearization point; later revocations cannot recall already-authorized bytes.

Persist encrypted ciphertext, 12-byte random nonce, 16-byte tag, AES-256-GCM algorithm and key version; keep versioned 32-byte keys in a secret provider, outside artifacts/logs. AAD binds version and an unambiguous tenant/subject/job/format tuple. Job selection, provenance and expiry are trusted immutable database metadata. Enforce the same 24-hour expiry, 50 selected-resource and 5 MiB plaintext bounds; failed generation never yields a partial ready artifact. Add retention cleanup and operational quotas before exposing the endpoint. The current serializer bounds stored/released artifacts but materializes source JSON before its size check, so the production snapshot adapter must also bound source allocation and fail on excess rather than truncate.

`findAuthorized` must freshly check actor access to the durable selection before returning even expired metadata. Denied or unknown jobs return null without key lookup, expiry disclosure or audit. This initial lookup does not replace the final atomic release gate.

Production acceptance still needs real database rollback, restart/key rotation, tenant isolation, revocation-versus-commit concurrency and independent rows/counts transaction tests. In-memory tests prove service orchestration and adapter behavior, not database durability or deployment readiness.
